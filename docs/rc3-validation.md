# RC3 긴급 수정 및 검증 — NO-GO

## 실제 사용자 보고
Windows 11/Chrome RC2 설치, 기존 탭 탐색, 테스트 알림음은 사용자가 PASS로 보고했습니다. 작업 시작 감지는 FAIL, 대시보드는 확인 불가, 완료/자동 알림은 검증 불가, Windows 알림은 미확인이었습니다. [원본 보고 기록](rc3-user-validation.md). RC3은 사용자 환경에서 아직 재검증되지 않았습니다.

## 원인 분석 및 수정

실제 ChatGPT DOM이나 실패 당시 메시지 로그는 확보하지 못해 **근본 원인은 확정되지 않았습니다**. 코드상 재현 가능한 위험을 수정했습니다.

- RC2는 SPA 내 sender.url의 경로가 이전 문서 주소로 남을 가능성을 고려하지 않고 현재 경로와 강제 비교했습니다. RC3은 발신 확장 ID·프레임·호스트를 검사하고 `tabs.get`의 현재 URL을 확인합니다. 경로 불일치의 짧은 경쟁은 제한적으로 재시도합니다. 전환 과정에서 루트의 시작 이벤트만 동일 문서에 한해 허용하고, 이전 경로의 완료 이벤트는 허용하지 않습니다.
- `/`에서 새 `/c/…`로의 이동이 최근 제출 직후 일어나고 동일 문서의 실행이라는 조건에서만 작업 ID를 이어 갑니다. 수동 대화 이동, 재접속, 문서 불일치, 이전 완료 및 검증 불가능한 이동은 초기화합니다. 이어받기 거부 시 확인 불가로 돌아가며 완료를 추측하지 않습니다. 문서 ID를 제공하지 않는 환경은 안전하게 이어받기를 거부합니다.
- 입력창의 ID, composer test ID, 폼 내 contenteditable, 한영 레이블을 검사하고 Stop test ID, 한국어/영어 레이블, composer 내부의 짧은 중지 레이블을 보완했습니다. 실제 DOM과의 일치는 미검증이며 화면 변경 시 계속 실패할 수 있습니다.
- 각 탭의 **진단** 버튼은 Content Script 응답, Worker의 마지막 ACK/거부/전달 실패, 입력창 감지 전략, Stop 표시, 감지 단계 등을 표시합니다. 이 결과는 추측으로 작업 상태를 바꾸지 않습니다. 메시지 거부는 진단 모드와 관계없이 시각·고정 사유 코드만 로컬에 최대 100개 남깁니다. 상태 전이 기록은 선택형입니다. 제목, URL과 본문은 진단 로그에 포함하지 않지만 시각은 민감할 수 있습니다.

## 실행 결과

- Node 상태/모의 Chrome API 회귀: **24/24 PASS**, [로그](rc3-unit-test.log).
- Playwright + Chromium headless shell에서 **모의 DOM**: 한영 제어, 신규 대화 SPA 이동, 수동 전환, 메시지 ACK, 거부 후 안전한 초기화, 도구 대기, 중단 등을 통과. [로그](rc3-browser-mock.log). 실제 확장 등록이 아닌 모의 `chrome.runtime`입니다.
- 실제 확장 로드 E2E: [재실행 가능한 테스트](../tests/browser/extension-e2e.cjs)를 추가하고 이 환경의 Chromium 158 headless shell로 시도했으나 서비스 워커 등록 대기 12초가 초과되어 **FAIL**. [로그](rc3-extension-attempt.log). 실제 Chrome/확장 환경 성공으로 간주할 수 없습니다. 확장 기능을 지원하는 Chromium 실행 파일이 있는 환경에서는 `npm ci` 후 `CHROME_PATH=경로 npm run test:extension`으로 재실행하세요. 이 테스트는 ChatGPT 서버가 아니라 요청을 가로챈 로컬 픽스처를 사용합니다.
- 빌드 성공. 소스·dist·ZIP의 12개 파일 바이트가 일치함을 확인. `gpt-task-manager-rc3.zip` SHA-256: `bd3b95cf1a9d441b1371521de853c804d594c27b62ccd9bcefeec92464e04c5b`.
- 실제 로그인된 ChatGPT, Windows 데스크톱 알림, 오디오 및 실제 탭 다중 부하에서 RC3 미검증. 오프스크린 알림음의 RC2 사용자 보고를 RC3 테스트 결과로 재분류하지 않습니다.

## 사용자 재검증

1. 원격 RC3 ZIP을 다운로드하고 별도 임시 폴더에 압축을 풉니다. 기존 압축해제 확장 폴더의 파일을 RC3 파일로 덮어쓴 뒤 `chrome://extensions`에서 확장의 **새로고침** 버튼을 누릅니다. 확장을 삭제하면 기존 로컬 설정도 삭제될 수 있습니다. ChatGPT 탭도 새로고침합니다. 다른 폴더를 새 확장으로 추가하면 중복 설치와 별도 데이터가 생길 수 있습니다.
2. 확장 팝업의 각 탭에서 **진단**을 누릅니다. 주입 확인, Worker 메시지 응답 확인, 입력창 감지 전략을 확인합니다. 주입 실패는 ChatGPT 탭 새로고침 및 확장 사이트 접근 권한을 확인합니다. 입력창 미감지는 로그인, 페이지 로딩, 팝업/대화 화면 상태를 확인합니다.
3. 기존 대화에서 새 요청을 제출하고 생성 중 다시 진단하여 Stop 표시·단계와 대시보드 상태를 비교합니다. 새 대화를 열어 제출 후 `/c/…`로 URL이 바뀌는 경우에도 반복합니다. 한국어·영어 UI, 수동 중지, 다른 대화로 이동, 도구 호출 중간 공백, 완료 후 정확한 1회 알림 및 클릭 이동을 확인합니다.
4. 실패하면 **진단 로그 → 로그 보기**에서 고정 사유 코드와 시각만 확인하고, 탭의 진단 결과와 함께 공유할 수 있습니다. 공유 전에 시각을 검토하고 대화 제목·URL·본문·계정 정보가 포함된 스크린샷은 제거하세요. 로그 삭제 버튼으로 지울 수 있습니다.
5. 테스트 알림과 실제 답변 완료 알림은 별개입니다. Windows 알림 권한과 실제 소리/바탕화면 표시를 별도로 확인합니다.

## 남은 위험

중간 응답·도구 호출 후 표시되는 복사 제어와 10초 안정화만으로 실제 최종 답변을 절대적으로 증명할 수 없습니다. 긴 중간 공백에 오탐이 가능하고, 반대로 짧은 생성·변경된 DOM·늦은 URL 변화·새로고침·기존 생성 중 진입에서 알림이 누락될 수 있습니다. Worker 저장과 알림 사이 종료 시 누락 가능성도 남습니다. 실제 확장 E2E와 실제 서비스 재검증이 완료될 때까지 중요한 작업의 완료 판단을 확장에 의존하지 마세요.

기존 [309개 업무 원장](task-ledger.csv)은 RC2 시점의 분류로 보존했습니다. RC3 사용자 검증과 수정 결과는 이 문서에 별도로 기록하며, 실서비스 확인 없이 기존 상태를 완료로 변경하지 않았습니다.
